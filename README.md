# 知新 · 个人文献雷达

[打开网站](https://liuhongwei2018.github.io/zhixin-literature/) · [云端运行记录](https://github.com/liuhongwei2018/zhixin-literature/actions)

独立的个人文献追踪后台与公开阅读清单。四个方向分别检索、按稳定标识符合并并生成可解释的个人 HOT。文献推送关闭。

## 自动同步

GitHub Actions 每 12 小时运行，计划北京时间 **08:17、20:17**。也可在 Actions 的 **Sync literature and publish HOT** 页面点击 **Run workflow** 手动补跑。GitHub 定时任务可能延迟，不能作为秒级定时服务；以网页实际数据时间和运行记录为准。公开仓库长时间无活动时 GitHub 可能暂停定时任务，需在 Actions 重新启用。

来源为 PubMed、Europe PMC、arXiv、bioRxiv、medRxiv。PubMed 同时检索 CRDT 新收录与 MDAT 更新；Europe PMC 同时检索 FIRST_IDATE 与 UPDATE_DATE，按日分区并核对命中数、返回数及唯一记录数。补充预印本源遍历近期版本或近期有序前缀。API 失败、数量漂移、重复分页、单日超限均保留为未完成，不标成零结果。

每轮滚动重扫最近 7 天，周一扩大至 28 天；持久化按来源和日期保存补扫状态，离线或漏跑的日期继续补扫。当前两天优先，其后处理旧缺口。429 的 Retry-After 按来源保存，失败不轮换地址、账号或代理。单轮有预算上限，未完成内容留待下一轮。

六小时内对未完成轮次再次运行，会复用仍有效的已完成窗口并优先补齐缺口，运行记录标明 recovery；下一次正常 12 小时轮次仍执行滚动重扫。Europe PMC 临床更新及异常分页改用互斥发表日期分区，每个叶分区仅一页，另查日期缺失记录，并核对父子计数与最终标识符并集；发表日期只作分区键，不改变更新检索范围。PubMed 长查询用其支持的表单 POST，400 最多重试三次，429 单独等待。

## 四个可调整方向

1. CHIP、克隆性造血、mCA、Y 染色体嵌合缺失。避免把裸 CHIP/MCA 缩写当成明确主题。
2. AI 医学影像，含影像组学、放射与超声影像、数字病理及眼科影像，要求实际影像输入线索。
3. RNA、单细胞/单核、空间组学、CUT&Tag/CUT&RUN、ATAC、GWAS 的方法与应用。应用场景与人体临床距离计入相关性，保留子方向代表。
4. 病案、EHR、登记、理赔及临床数据观察性研究。明确数据库与结局的组合不强制题目含 epidemiology/cohort。

具体查询在 `queries.json`；本地语义核对在 `topics.py`。更改词表后立即触发同步。关键词与自动分类不保证零漏检，来源分页完整与语义召回率是两种不同的验证。

## 个人 HOT v1

HOT 是个人阅读优先级，**不代表论文科学质量或全网热度**。

| 成分 | 满分 | 依据 |
| --- | ---: | --- |
| 主题与应用相关性 | 40 | 四方向本地语义核对，低相关场景降权 |
| 新近性 | 30 | 原始发表日期按 14 天尺度指数衰减；较早预印本的近期版本单独标记并限制加分 |
| 研究设计或方法线索 | 20 | 类型、外部验证、多中心、前瞻性、方法评测、代码可用等题录/摘要线索 |
| 元数据完整度 | 10 | 摘要可用、完整日期、稳定标识符 |

评论、综述和研究方案单独标记；这些线索不能替代全文质量评价。只把近期、主题合格、无撤稿及标识冲突的条目纳入 HOT。

Europe PMC `citedByCount` 单独展示来源与采集时间。仅在同类、同一两分区间内辅助近似同分条目排序；缺失不填零，缺失条目的基础位置保持。MED、PMC、PPR 计数不相加。只有同一来源、同一实体和同一指标在两次采集实际间隔 12–36 小时后才计算增长；首次记录、陈旧记录、来源回调均不伪造增长率。来源计数变化不等于精确的引文发生日期。

默认每方向展示前 100 条，组学可额外补充缺少的子方向代表；跨方向文献只存一份。周汇总数据在 `weekly.json`，不发送文献通知。

完整检索与公开缓存分开：每条返回记录均筛选，运行缓存每方向保留前 1,000 个 HOT 候选及组学子方向代表，另有少量撤稿/标识冲突隔离记录。目录数量是缓存数量，来源命中数见按日检索状态。展示条目保留最近八次真实计数，其他缓存条目每个来源实体保留最新一次，避免长期运行因缓存无限增长而中断。公开清单是当前阅读目录，不是文献档案库。

## 去重与公开数据边界

PMID、DOI、PMCID、arXiv 标识和来源明确登记的预印本/正式发表联系可用于合并。不依赖相似题名强行合并；冲突进入待核。Research Square 独立 DOI 版本只在有明确版本关系的公开规则下合并。

公开仓库保存最小题录、分类与特征、分数、来源观察记录和聚合检索状态。**不保存摘要全文、私人数据库、私有配置、访问令牌、本机路径或原始科研数据。** API 临时响应仅存在于执行环境的 `.run/` 中，网站发布严格限于静态文件白名单。原知新及本机独立试运行环境不受此版本影响。

## 运行与验证

Python 3.12；安装 `requirements.txt`，运行 `python -m unittest -v test_cloud test_export_public`。`python sync.py` 执行检索；`python sync.py --validate` 核验公开结构与敏感字段；`python sync.py --build-site site` 生成网站白名单。

首次仓库包含已核对公开题录的有限种子，初始覆盖状态为待验证。只有真实云端运行才标记云端已接通；运行缺口继续显示。完整源状态见网站覆盖表与 `scan_state.json`，源查询及分页完整不等于已经验证所有方向的科学召回率。


## 期刊资料与作者

清单显示来源作者名单、发表日期和期刊，并匹配 2025 年影响因子及 2026 年新锐分区。期刊查询表经项目所有者授权公开，按 ISSN/eISSN 优先、唯一完整名称或官方缩写其次匹配；冲突、缺失和预印本不以零值代替。新锐分区保留学科信息，不等同于 JCR 四分位或中科院分区。期刊指标不进入 HOT 计算。作者元数据通过原有公开来源更新；历史条目尚未补全时显示“来源待补”。
