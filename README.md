# 知新 · 文献阅读清单

个人文献追踪项目的公开阅读页面，按四个方向整理进展：CHIP / mCA、AI 医学影像、组学方法与应用、病案与临床数据研究。

网页使用 GitHub Pages。检索、完整候选池、标识去重和漏跑补扫继续在独立后台运行。这里仅保存公开文献题录、来源链接、阅读顺序、少量自撰中文导读及来源覆盖状态；没有复制本地后台、数据库、日志、配置或完整摘要。

## 当前状态

试运行。网页显示的时间是后台实际生成清单的时间，不能以部署时间冒充新一轮检索。未完成的来源任务会在网页显式标注；超过 36 小时未更新会提示。

检索计划为每天北京时间 08:00，周一汇总；运行环境需在线。公开页面是后台清单的镜像。GitHub Pages 不运行本机 Python 检索服务，此仓库通过 GitHub 管理的 Pages 工作流部署静态页面，不声称独立完成云端检索。公开页面的定时同步尚未接通。正式 HOT 和文献推送均关闭。

## 检索与阅读原则

主检索源为 PubMed，Europe PMC 补充收录与题录更新，arXiv、bioRxiv、medRxiv 补充预印本。来源日期口径分别记录；新收录不等同于新发表。预印本明确标记。

CHIP / mCA 排除芯片、ChIP-seq 和大脑中动脉缩写误命中。影像方向要求医学影像语境。组学覆盖 RNA / 转录组、单细胞 / 单核、空间组学、CUT&Tag / CUT&RUN、ATAC 和 GWAS，区分方法与应用。临床数据方向兼顾明确数据库路径与临床观察设计，避免强制标题含 epidemiology 造成漏检。

四个方向分别排序，同篇多标签。后台按 DOI、PMID、PMCID、arXiv ID 和明确的预印本发表链接去重，不按相似题名自动合并。公开目录只展示每方向当前前 30 条阅读候选，候选总量与展示数量分开。

发布前另核对公开清单。`publication_rules.json` 记录有原始来源证据的展示修正：排除一篇把数值网格 single cell 误识别为生物单细胞的论文；根据 Crossref 的明确版本关系合并一组 Research Square v1/v2。该层只修正公开展示，保留后台原始统计口径；这些发现也说明后台分类与版本识别仍需继续验证。

阅读分数由主题、发表日期、文章类型线索、元数据完整度和应用场景构成；组学列表兼顾技术多样性。分数不是质量评分，未经全文科学评价，也不用于跨领域比较。首批中文导读基于题录和摘要分类核对，仍需阅读原文判断。

## 更新公开数据

`export_public.py` 从明确选定的本机服务 API 或只读报告生成白名单字段。部署前运行：

```sh
python3 export_public.py --url http://localhost:8975/api/daily --output readings.json
python3 -m unittest test_export_public -v
```

如需保留已核对的中文导读，可通过 `--notes` 指定仅含公开文献导读的文件。每次仅提交核验后的公开文件，不提交运行目录。在 `main` 分支中的公开页面或数据提交更新后，GitHub Pages 自动重新部署。导出边界测试需在提交前运行。

本仓库不会保存访问令牌。原始后台和原知新保持独立。收藏只存在浏览器的本地存储；页面不使用分析追踪脚本、第三方字体或外部 AI 服务。

## 部署

在仓库 Settings → Pages 中选择 Deploy from a branch，再选择 `main` 和 `/ (root)` 并保存。GitHub 管理构建与部署，不需要复制本机服务。可参考 [GitHub Pages 发布来源文档](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。部署结束后需打开实际站点核对清单和覆盖状态。

文献题名及元数据归原来源所有；页面提供原始链接，自撰导读仅用于研究阅读。项目尚未给出检索召回率、准确率或连续运行验收结论。
